# 文章发布：核心目标与验收标准

1. **一篇文章**：标题 + 富文本正文（内嵌本机图片可选 → `mediaPaths`）+ 独立封面（抖音文章双列封面为竖版 3:4；头条横版必填、B 站横版可选）
2. **多方分发**：今日头条、哔哩哔哩专栏、抖音发文章；同平台可多选账号，各一份 Target
3. **个性化**：正文始终共用；其余按账号走独立平台表单
4. **持久化**：保存草稿（Content `type=article` + Targets + overrides + 封面 BLOB）
5. **与图文区分**：文章是文本混合图片（插图在正文里）；图文见 [`publish-graphic.md`](publish-graphic.md)
6. **约束**：不改 `components/ui/**`；用户文案克制；平台表单不混进单组件
7. **标题**：共用标题最多 60 字，不随所选账号变化；空白不计字数，纯空白视为未填写。账号侧按最终使用的标题独立校验（单独标题为空时沿用共用标题），批量设置取所选平台最严上限。

### 标题空白与特殊字符

- 共用标题、账号独立标题及批量标题均在离开输入框和保存时去掉首尾空白，将连续空白（含全角空格、制表和换行）整理为一个普通空格。
- 共用标题仍按产品约定忽略空格计数；账号侧以整理后实际使用的标题计数，单个分隔空格计入长度。账号计数目前按 Unicode 码点处理，不代表平台已经验证的算法。
- 保留常用标点、特殊符号及 Emoji，不采用未经证实的字符允许列表，也不拆解组合表情。组合表情可能包含多个码点，不能直接当成一个字符。
- 2026-10-01 实测入口检查：三个平台创作者中心均要求登录，未进入实际文章编辑器。连续空格的保留方式、符号接受范围、简单与组合 Emoji 的计数和接受情况仍待登录后核实；不以视频或图文轮播规则替代文章规则。

## Cookie 接口发布（2026-10-06）

- 桌面 main 为每个账号任务创建独立、非持久化 Chromium 会话，注入绑定账号的 Cookie。隐藏页面承载平台当前的签名与上传 SDK，发布直接调用平台接口，不填表或点击发布；平台要求验证时显示官方验证窗口。任务结束清除 Cookie、存储、缓存并关闭连接。
- 抖音：正文转换为 Markdown，正文图片引用上传 URI；向 `/web/api/media/aweme/create_v2/` 提交 `media_type=43` 与 `long_article_version=1`。带标题、摘要、封面、自由文本话题、可见范围和定时时间。当前提交校验要求正文至少 100 字，最多 20,000 字。
- 头条：正文转换为平台 HTML，图片携带上传地址、URI 与尺寸；向 `/mp/agw/article/publish` 提交表单。`save=1` 为发布，传入有序的单图/三图/无封面、广告、首发、赞赏、同步微头条与作品声明。执行前重新读取赞赏额度与发布策略；不满足已选择的权益时停止提交，避免静默改变设置。当前平台仅选一项作品声明，引用平台内容需来源账号，尚无对应资源选择器时提示用户在创作者中心完成。
- B 站：使用新版 `/x/dynamic/feed/create/opus`，正文为 opus 段落 JSON，包含图片、标题、引用、列表、代码和内联样式。使用当前账号的 `bili_jct`、WBI 参数和官方环境 SDK，提交自定义封面、评论、原创、可见范围与定时时间；不套用旧专栏 draft/submit 接口。
- 只有平台明确成功且返回有效作品编号才记录成功。平台拒绝、登录失效与验证要求返回可读提示；提交断线、超时或缺失编号记录为“尚未确认发布结果”，先到平台核对，不能自动重复提交。取消已发出的请求会等待回执，确定成功的结果不会被覆盖为取消。
- 文章、图文和视频始终走真实平台适配器，不再提供模拟成功的环境开关。
- 抖音使用原生客户端签名与二次验证；B 站明确拒绝且提供验证凭据时运行官方验证 SDK，完成后重新签名、最多重提一次。未知结果不走该重试流程。
- 抖音初始化会按需加载当前上传模块，并为每次探测使用独立标识；授权失效在原网址显示登录页时，也会提示重新授权。平台脚本协议变化或初始化超时会在提交前停止。

## 正文插图与持续写作（2026-10-01）

- 工具栏多选、拖入正文和粘贴图片均在当前光标插入；无本机路径的 PNG 先另存。连续插图后回到正文段落继续输入；读取期间用户继续输入或移动光标时保留新的位置。
- 图片上、下边界可点击进入相邻正文；没有相邻段落时创建段落。选中图片后按 Enter 可继续写正文；图片说明内按 Enter / Escape 回到图片后的正文。
- 操作条采用图片底部半透明深色小条，显示「裁剪｜替换｜删除」，选中不改变正文排版；说明输入一直保留位置，最多 50 个 Unicode 码点，以 `figure/figcaption` 存储。图片支持拖动调整正文位置。参考当前头条图片居中且未铺满正文的表现，编辑预览保持比例、宽度不超过正文、高度不超过 25rem 或视口高度的 60%（取较小值），小图不放大；该显示约束不写入平台正文，也不改变原文件。
- 图片处理仅支持裁剪：独立面板提供原图比例、1:1、2:3、3:2、9:16、16:9 和自由比例，可拖动裁剪框与四角，方向键微调。取消不修改正文；确定自动将结果保存为本机新 PNG 并替换图片，保留原图，不再弹出另存对话框。派生图片在本机数据目录 `article-images` 下保存，仅作为正文路径引用，不建立独立素材库；粘贴无路径图片仍由用户选择保存位置。替换保留说明；删除、替换与裁剪可撤销/重做。删除最后一张图同步清空素材路径。
- 头条登录态页面已观察到图片选中操作与「请输入图片描述(最多50字)」。本任务依用户最新要求仅实现裁剪及插图后的正文编辑，不包含滤镜、模板、图片文字和平台图库。

### 发布格式边界

- 草稿 HTML 属于内部格式，不直接交给文章平台适配器。桌面发布入口先解析为受限正文节点、本机图片路径和说明；移除交互属性及不支持的活动内容。
- 每张图片必须可解析为本机绝对路径，并列在当前文章素材中；未解析图片直接阻止发布。平台适配器只接收解析结果，不接收原始 `body`。
- 接通真实平台时先上传图片，取得平台地址或素材标识，再转换正文。HTML 转换器要求适配器明确提供已验证的标签集合与图片/说明输出方式；未上传、仍含本机地址或内部标记、格式不支持时不得提交。
- 三个平台适配器均按各自当前编辑器协议转换正文；图片上传失败或正文无法转换时停止提交。真实提交范围与平台可见性见上方验收记录。
