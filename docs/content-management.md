# 作品管理

作品管理统一展示文章、图文和视频，保留服务端搜索、类型筛选与每页 20 条的分页。

## 状态规则

列表状态由分发账号结果优先决定，不使用内容的历史 `published` 标记作为成功依据。内容级 `draft/published` 数据及发布编排不变，无需数据库迁移。

| 优先级 | 条件                               | 筛选入口 | 列表标签 |
| ------ | ---------------------------------- | -------- | -------- |
| 1      | 任意账号排队或运行中               | 发布中   | 发布中   |
| 2      | 任意账号失败或取消，且无账号运行中 | 需要处理 | 需要处理 |
| 3      | 至少一个账号，且所有账号成功       | 已完成   | 全部完成 |
| 4      | 部分账号成功，其余未发布           | 待发布   | 部分完成 |
| 5      | 无发布结果，内容为草稿             | 草稿     | 草稿     |
| 6      | 其他无发布结果内容                 | 待发布   | 待发布   |

取消数量独立显示，不计入失败数量。成功表示发布流程完成，不代表平台审核通过或已公开；目前不接入审核结果。

## 筛选与数量

`GET /contents` 支持 `managementStatus=draft|pending|publishing|needs_attention|completed`，无状态参数时查询全部。响应新增 `counts`，包含全部及五种状态数量。

类型和关键词同时作用于列表与状态数量；数量忽略当前状态选项和分页。关键词仍匹配标题、正文及标签，并将 `%`、`_` 等视为普通字符。SQLite 通过分发记录计算状态、筛选后再分页，排除软删除作品，使用更新时间及 UUID 保持排序稳定。

## 账号详情与操作

- 详情显示平台图标、平台名称、当前账号名称、状态和开始/完成时间。账号已移除或读取失败时展示对应说明，不展示账号内部 ID。
- 成功记录有有效 HTTP/HTTPS 地址时提供「查看平台作品」，由已有桌面外链机制打开系统浏览器。
- 授权失效引导到媒体账号重新授权；素材缺失引导回编辑页；其他失败可重试，取消可重新发布。每次仅重试选中的账号，不触发已成功账号。
- 列表草稿摘要显示已选账号数，其余作品显示分发结果；摘要为普通文字，右侧保留一个分发详情入口。
- 草稿显示「继续编辑」；其他作品显示「编辑」，在编辑页说明保存不会修改平台作品。发布期间列表不允许编辑或删除。
- 删除位于「更多」菜单内，保留删除确认。单页底栏仅显示数量，多页才显示页码。
- 已选可发布账号的作品可在「更多 → 开始分发」提交到应用级队列，文章、图文和视频共用调度；失败账号重试也进入该队列。
- 详情仅显示实际开始/完成时间；有成功记录时才显示平台审核说明。
- 删除仅移除本机作品及关联分发记录，不删除平台作品或原始媒体文件；本轮不提供回收站与恢复入口。

## 更新机制

- 发布进行中或本页发起重试时，每 3 秒刷新；空闲时每 15 秒刷新。窗口隐藏时跳过轮询，回到窗口时刷新。
- 更新保留现有列表，不反复替换成骨架。请求失败保留已加载的数据，显示简短错误提示。
- 打开的分发详情按作品 ID 独立读取，即使重试成功后作品退出当前筛选，详情仍更新。
- 筛选切换、关闭详情与页面卸载会丢弃旧请求结果；结果变少后回到合法页。
- 账号信息初次进入、窗口聚焦及账号同步事件时更新；「刷新」与「刷新详情」也可重新读取。

本轮不包含平台/账号筛选、复制作品、批量操作、回收站和平台审核状态。

## 后台分发

任务接受后由 Electron 主进程负责开始账号任务、执行平台适配器并将结果保存到本机 Server。切换页面、刷新页面、最小化或隐藏到托盘不会中断分发，执行不依赖 renderer 回写结果。

偏好设置的「分发 → 同时分发数量」默认为 3，支持用户输入正整数，离开输入框或按回车后保存并生效。额度由整个应用共用；同一媒体账号的任务始终串行。提高额度立即启动符合条件的排队任务；降低额度不会中断已运行任务，而是在后续调度时生效。设置保存到本机用户数据目录，重启仍保留。

一个任务失败不会阻塞其他账号；结果保存暂时失败时只重试保存，不重新发布。真正退出应用会停止队列，将未完成任务记为取消。应用重新启动时也会核对上次遗留的排队/运行状态，改为取消；不自动重复发布。用户可以先核对平台上的结果，再选择重试。

文章支持抖音、今日头条和 B 站；图文支持抖音、头条、小红书与视频号；短视频支持抖音、小红书、头条、B 站与视频号。

## 统一观测

侧栏「分发队列」是全局入口，数字表示正在执行与等待的账号任务总数，提示中分别显示发布、等待和需要处理的数量。文章、图文和视频共用四个视图：正在发布、等待中、需要处理、近期完成；按作品分组展示平台账号、实际阶段、耗时及结果。

统计以账号任务为单位，忽略分页与当前视图；草稿的未提交账号和已删除作品不计入。作品摘要的「已处理 / 总数」统计该作品当前所有已提交账号，成功、失败和取消均属于已处理。近期完成展示最近 24 小时的成功结果，其它失败和取消仍可在「需要处理」中找到。每个账号目标保留最新状态，当前界面不作为每次重试的永久历史。

状态筛选集中在页头，以「项任务」标注统计口径。列表共用一套平台账号、发布状态、耗时 / 时间和操作列，作品分组标题标明全部账号的处理数量及当前显示范围。等待时长从本次入队计算，执行耗时优先使用实时任务的开始时间，不沿用上一次发布结果。空态可直接转到等待或待处理任务；素材缺失提供对应作品的编辑入口。

主进程快照区分等待空闲位置、等待同账号任务、平台执行阶段和保存结果。平台完成但本机结果保存正在重试时显示「正在保存结果」，不重新发布；观测通道不传 Cookie、原始平台调试消息或本机素材路径。

应用布局统一订阅变化并读取当前快照，切换页面不建立重复订阅；刷新页面重新读取，窗口恢复可见时更新。前台每 3 秒复核已保存结果；结果查询最迟 10 秒超时，查询缓慢不会阻塞实时阶段更新。读取失败保留已有数据并提示状态未更新，首次读取失败显示未知状态。作品入口可直接打开分发详情；失败目标可单独重新发布，登录失效提供重新授权入口，未知回执需确认已核对平台后才允许重新发布。

## 分发验收

桌面端常规测试覆盖队列调度、设置校验、任务失败、结果保存重试及退出边界。真实 API / SQLite 的集成验收使用临时数据库、虚拟账号和模拟发布执行器，不访问平台，也不使用日常作品数据。

先在 `server/` 执行 `npm run build`，再在 `desktop/` 执行：

```sh
PUGYING_RUN_DISTRIBUTION_ACCEPTANCE=1 npm test -- electron/main/distribution-acceptance.test.ts
```

验收覆盖默认并发 3、提高及降低额度、跨作品共享额度、同账号串行、素材失效、设置持久化、中断恢复及跨作品观测查询。测试结束会关闭临时 Server 并清理验收数据。
