# 图文发布：核心目标与验收标准

1. **一条图文**：多图轮播（有序 `mediaPaths`）+ 标题 / 文案分离（纯文本 `body`）+ 竖版封面为主（可自首图裁切）
2. **多方分发**：抖音图文、小红书、视频号图文；同平台可多选账号，各一份 Target
3. **个性化**：图片与文案共用；其余按账号走独立平台表单
4. **持久化**：保存草稿（Content `type=graphic` + Targets + overrides + 封面 BLOB）
5. **与文章区分**：图文是图文分离；文章是富文本内嵌图，见 [`publish-article.md`](publish-article.md)
6. **约束**：不改 `components/ui/**`；用户文案克制

## 存量

- 历史上 `type=article` 且按「多图 + 竖封面」发布的内容，迁移后为 `graphic`

## 抖音账号表单对齐

2026-10-04 核对登录后的图文发布页。保持「通用内容 + 账号设置」布局，按后台字段含义与规则组织账号区，不复制后台整页布局。

- 基础信息：账号标题（20 字）、话题、封面。图片顺序与作品描述继续在通用区编辑。
- 扩展信息：自主声明（无需声明、AI 生成、个人观点、转载、营销推广、虚构演绎）。
- 发布设置：谁可以看、保存权限（允许／不允许）、发布时间（立即／定时）。选择定时立即生成有效时间，选择器限制沿用现有 2 小时至 14 天规则，平台边界仍待进一步实测。
- 权限与声明按账号存入 Target overrides；发布下发话题、权限和声明。话题作为描述中的 `#话题` 文案追加，合计按 1000 字检查；平台话题搜索与关联标识尚未接入。
- 适配器按实际字段文案定位标题与描述，使用编辑输入填写正文，不静默截断。权限、声明或定时设置无法确认时停止自动提交，保留窗口供人工核对。

后续平台数据选择器：合集、音乐、位置、关联热点、@ 好友、官方活动及同时发布渠道。必须读取该账号的真实候选项并保存平台标识，不以普通文本输入或虚构选项代替。扩展项接入后采用默认折叠的搜索选择区，已选项展示摘要；自主声明直接可见。

待实测规则：标题／描述必填性、话题上限、图片数量／格式／大小以及定时与可见性的联动。
